# 工作台 · 设计系统

> 这份文档是界面的「宪法」：改界面前先在这里找对应的令牌或规则，不要临时写死颜色和间距。
> 令牌唯一实现在 `src/WorkStation.App/Styles/Tokens.axaml`，控件样式在 `Styles/App.axaml`。

## 1. 设计取向

用 UI/UX Pro Max 引擎按产品类型推导，匹配到 **Dashboard / Admin**（置信分 21.0），
推荐风格 **Data / Dashboard**（备选 Material、Industrial），配色口径是
「一个强调色 + 中性灰 + 语义状态色」。

引擎给出的默认调色板是红色系（Calm Analogous 001），那是它按 BM25 词面匹配的产物，
对一个任务管理工具不合适，已人工校正为蓝色单强调色方案。

落地三条原则：

1. **内容优先于容器** —— 描边和底色只用来分层，不用来装饰。列表行默认无边框，靠间距分组。
2. **一个强调色** —— 蓝色只出现在「当前在哪」「主操作」「进度」三处。其余靠灰阶拉开层次。
3. **红色是报警，不是装饰** —— 逾期、阻塞、删除确认才用红。列表里的删除按钮是灰色文字。

## 2. 色彩

浅色 / 深色各一套，全部走 `ThemeDictionary`，控件用 `DynamicResource` 引用。

| 角色 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `BgBrush` | `#F5F6F9` | `#0E1116` | 页面底色（比分层面深一档，卡片才浮得起来） |
| `BgPanelBrush` | `#FFFFFF` | `#161A21` | 卡片、抽屉、侧边栏 |
| `BgSunkenBrush` | `#EDEFF4` | `#1C222C` | 内嵌区域、胶囊、分段控件底槽 |
| `BgHoverBrush` | `#F1F3F8` | `#1F2631` | 悬停 |
| `BgColumnBrush` | `#EAEDF4` | `#131820` | 看板列：浅色下比页面深、比卡片浅；深色下介于页面与卡片之间 |
| `LineBrush` | `#E4E7EE` | `#262D39` | 常规描边、分隔线 |
| `LineStrongBrush` | `#D3D8E2` | `#34404F` | 悬停描边、勾选框 |
| `TextBrush` | `#12161D` | `#E9ECF2` | 正文 |
| `TextSecondaryBrush` | `#3F4855` | `#C2CAD6` | 次级正文 |
| `TextDimBrush` | `#667085` | `#8B95A6` | 元信息（`.dim`） |
| `TextFaintBrush` | `#98A2B3` | `#5E6878` | 仅图标、箭头这类非文本元素 |
| `AccentBrush` | `#2F62E8` | `#6E97FF` | 主色 |
| `AccentSoftBrush` | `#EBF0FE` | `#18243D` | 选中底、激活导航 |
| `DangerBrush` | `#C0392F` | `#F0796F` | 逾期、删除 |
| `WarningBrush` | `#9A5B06` | `#E3A44A` | 警告 |
| `SuccessBrush` | `#0F7A57` | `#43C793` | 完成 |

**对比度口径**：`TextBrush` / `TextSecondaryBrush` / `TextDimBrush` 对各自背景均 ≥ 4.5:1；
`AccentBrush` 对白底 5.2:1，白字压其上同为 5.2:1。`TextFaintBrush` 达不到 4.5:1，
**只允许**用于装饰性图形，不得承载文字。

**项目色与优先级色**不走主题令牌，由视图模型直接给中间调 hex：同一份色值要同时在
白底和 `#161A21` 上看清，浅色系的语义色在深色主题会糊。

## 3. 字号阶梯

只有 6 档，新增字号先问「能不能复用已有的」。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `FontDisplay` | 22 | 页面标题（配 `TextBlock.page-title`，字距 -0.3） |
| `FontH2` | 16 | 抽屉标题、设置分组标题（`TextBlock.section-title`） |
| `FontBody` | 13.5 | 正文、列表标题 |
| `FontInput` | 14 | 输入框、下拉、日期字段的值 |
| `FontSm` | 12.5 | 按钮、表单标签、副标题 |
| `FontXs` | 11.5 | 元信息、路径、分组标题 |
| `FontMicro` | 10.5 | 胶囊文字、环内百分比 |

## 4. 间距与圆角

间距只用 4 的倍数：`4 / 6 / 8 / 12 / 16 / 20 / 24 / 28`。

- 页面左右内边距统一 `28`（`PagePadding`），标题区 `28,24,28,18`（`PageHeaderPadding`），
  各页工具栏一律 `28,0,28,16` —— 早先项目页误用了 `PageHeaderPadding`，标题和工具栏之间多出 24px 空白。
- 圆角只跟「层级」有关，跟控件高度无关，共三档 + 一个真圆：

  | 令牌 | 值 | 用在哪 |
  | --- | --- | --- |
  | `RadiusSm` | 4 | 一切控件：按钮、图标按钮、输入框、下拉、日期字段、导航项、筛选胶囊、计数胶囊、行 |
  | `RadiusMd` | 6 | 内嵌容器：合成框、统计块、看板卡片、任务卡、面板、Toast |
  | `RadiusLg` | 8 | 页面级容器：卡片、看板列、设置分组、命令面板 |
  | `RadiusPill` | 999 | 只给「本身就是圆」的元素：侧边栏数字徽标、完成圆点 |

  早先的 6 / 9 / 14 是按控件高度递增的，结果 40px 的看板列和 14px 的卡片都圆得像移动端气泡，
  同一排里 25px 的筛选胶囊和 34px 的下拉框圆角视觉深浅还不一致。改成固定三档后，
  同一行里的控件圆角完全一致，容器之间靠「内层比外层小一档」自然收敛。

## 5. 组件约定

### 按钮层级

| 场景 | 类 | 说明 |
| --- | --- | --- |
| 一屏唯一主操作 | `primary` | 强调色实底。`pointerover` 必须显式声明深一档，否则会被 Fluent 的默认悬停盖成灰底 |
| 危险操作 | `danger` | 实底红，**只出现在二次确认弹窗** |
| 列表行 / 卡片底部 / 工具栏操作 | `icon`（+ `sm`） | 26×26（行内 24×24）正方形，只有图标 |
| 破坏性图标 | `icon dangerish` | 静止与普通图标一致，悬停才转红 |
| 需要一眼看出是按钮的图标 | `icon tinted` | 淡蓝底 + 蓝字，悬停转实底。**只给「这一屏唯一动作」用** |
| 状态筛选 | `filter` | 胶囊，选中态 `active` = 淡蓝底 + 蓝边 + 蓝字 |
| 分段切换 | `seg` | 任务/项目看板、主题三选一，**保留文字**：图标表达不了「看板」 |

图标按钮的三条硬规则：

1. 图标必须是 `controls:Icon`，不是字形符号。`✕ ＋ ✎` 这类字符在不同字体下形态不一，
   而且没法统一线宽。
2. **必须有 `ToolTip.Tip`**。图标不承载文字，没有 tooltip 就等于一个匿名控件。
   `IconButtons_HaveGlyphAndTooltip` 这条用例守着它。
3. 颜色不单独设，靠 `Foreground` 继承：`Button.icon` 静止 `TextDimBrush`，悬停 `TextBrush`；
   `dangerish` 悬停 `DangerBrush`；`tinted` 用 `AccentBrush`。
   **`TextFaintBrush` 只给纯装饰图形**（进度环底、虚线框），不给可点图标。

> 类名不要叫 `accent`：Fluent 主题自带 `Button.accent`（系统蓝实底按钮），
> 会盖掉自定义样式。同理别用 `h1`–`h4`。

### 图标

实现在 `Controls/Icon.cs`，16×16 网格、1.5 描边、`PenLineCap.Round`，按 `Kind` 枚举取图形，
尺寸由 `Size` 给（默认 14，行内 13，列头 12）。现有 `Edit / Trash / Archive / Unarchive /
ArrowRight / Clock / Close / Plus / Calendar / Settings / Bell / Check`。

**颜色靠继承**：图标在按钮里时不用设颜色，取的是 `TextElement.Foreground`（按钮的 `Foreground`
会传导下来，悬停换色自动跟随）；单独摆在字段里才显式给 `Foreground`。要加新图标就加一个 `Kind` 和一段绘制，
不要在 XAML 里手画 Canvas——早先侧边栏四个图标是逐个 Canvas 拼的，改一次线宽要改四处。

## 5.1 输入框

输入框是一类控件的统一规范，`TextBox` / `ComboBox` / 日期字段都按它来：

| 项 | 值 | 原因 |
| --- | --- | --- |
| 值文字 | `FontInput`(14) + `TextBrush` | 用户自己敲进去的内容是这一屏的重点，比正文大半档 |
| 占位文字 | `TextDimBrush`（对白底 4.9:1） | 比正文弱一档但读得清；Fluent 默认的浅灰只有 2.2:1，整行看着像「说明也看不清」 |
| 描边 | `InputLineBrush`，悬停 `InputLineHoverBrush`，聚焦 `AccentBrush` | 比常规分隔线重一档，字段才有轮廓 |
| 光标 / 选区 | `AccentBrush` / `TextSelectionBrush` | 定位点要一眼能找到 |
| 尺寸 | `MinHeight 34`、内边距 `10,7` | 与 34 的下拉、日期字段同高，并排不会一高一矮 |

- 常规输入框聚焦：1px 强调色描边，靠 `TextBox:focus:not(.bare)`。
- **裸输入框（`TextBox.bare`）不许有描边**：它外面已经有容器，描边会直接压在文字上把首字切掉。
  焦点反馈交给容器——`Border.composer:focus-within` 把整个框的描边换成强调色。
- **下拉选项要原地同步，不能 `Clear()` 重建**：下拉框按引用记选中项。清空会让它先把
  `SelectedItem` 置空，补回来的又是「值相等的新实例」，属性变更被相等判断吃掉，
  `SelectionBoxItem` 再也不会被重新赋值 —— 表现就是「选了项目，框里却空白」。
  `ProjectOptionList.Sync` 按 Id 就地改名 + 移动，选中项始终是列表里的同一个实例；
  `ProjectOption` 也因此是 class 而不是 record（引用相等）。

> 全局不要再写 `Button:pointerover /template/ ContentPresenter` 这类覆写：
> class 选择器比 Fluent 的类型选择器更特化，会把主按钮的悬停态也一并吃掉。

### 卡片

`Border.card` + 固定 `Width` 的 WrapPanel。卡片内部四段：标题行（含状态）、描述
（**固定 34px 高度**，否则长短不一导致底部对不齐）、进度行（42px 环 + 统计）、
操作行（上方 1px 分隔线，`Margin` 负值拉满整宽）。

### 任务行

列宽 `3,20,*,Auto,Auto`，列间距 10：

1. 3px 优先级色条（`Border.priority-bar`），无优先级则隐藏
2. 20px 完成圆钮（`Button.check`）
3. 标题 + 元信息（`MetaText` 由视图模型合成，不在 XAML 里拼分隔符）
4. 截止时间（逾期转红）
5. 行内操作是两个图标（铅笔 / 垃圾桶），默认 `Opacity 0.5`，指针进入整行才恢复——
   否则每行都有两个可点方块，噪声盖过内容

**分组标题必须复用同一套列宽**（`3,20,*,Auto`），否则标题和任务标题的左边缘会差 27px。

### 顶部快速添加（合成框）

容器 `Border.composer`（高 40），两段：输入框 + 右侧一个 `icon tinted` 的加号按钮。
加号是该栏唯一的动作，用淡蓝底让它自己说明「这里能点」；不再用文字按钮，
文字在黑色描边里既不像按钮、又和占位文字抢同一行。

- **输入框必须显式 `VerticalContentAlignment="Center"`**（写在 `TextBox.bare` 里）。
  Avalonia 的 `TextPresenter` 默认会被 `MinHeight` 撑满整个输入框高度，而文字贴着行框顶部
  绘制，于是占位文字比同一行的按钮文字高 2.5px。加上之后行框缩到实际行高（18px）再居中，
  两者只差亚像素。
- **盒子中心对齐不等于文字对齐**：只比 `Bounds` 时输入框与按钮的中心都是 20，看着「已经齐了」；
  必须比对渲染出来的像素行（占位文字墨迹 14–26、按钮图标 15–25 才算齐）。
  回归用例 `Composer_TextAndButtonShareOneCenterLine` 同时守中心线与行框高度两件事。

### 抽屉

`Grid` 三段：固定头部（标题 + `icon` 关闭）、滚动内容、固定页脚（取消 / 保存）。
不再把按钮放在滚动区末尾——长表单里用户要滚到底才能保存。

### 日期字段（`Controls/DueDateField`）

不再用 `CalendarDatePicker` + `TimePicker` 拼一行：那两颗控件各带一套 Fluent 模板，
日期框右侧挂着一整块带边框的日历按钮，时间框又只在有日期时才出现，
抽屉里就成了「宽框 + 方块 + 冒号框」三截长短不一的控件。

- 折叠态是一颗输入框：`Button.field`（日历图标 + 值 + 右侧清除按钮），高 34、圆角 `RadiusSm`，
  和旁边的手填字段完全同高。没值时显示占位「不设置」（`TextDimBrush`），不是灰字空框。
- 展开态是 `Border.popover` 里的两栏：左边 `Calendar`，右边「时间（时:分）+ 今天 / 明天 / 完成」。
  **两栏并排而不是上下堆叠**：竖着放浮层高 450，抽屉里的字段在中段，下方放不下就只能往上翻，
  浮层会一路顶到窗口顶部；并排后高约 350，能稳稳落在字段下方。
- `ShowTime="False"` 用项目表单这类只要日期的场景，此时时间栏收起、文字里也不带时刻。
- 只给日期不给时刻时补 18:00（`DefaultTime`），比 00:00 有意义。

### 看板

一屏四列（`UniformGrid Columns="4"`），列间距由每列右侧 `Margin 0,0,12,0` 提供，
因此页面内边距用 `BoardPadding`（`28,0,16,24`）——右侧少 12，最后一列的右缘才与标题、
搜索框齐平。

- **列**：`Border.column`（`BgColumnBrush` + 1px 描边 + `RadiusLg`）；拖拽悬停整列换成
  `AccentSoftBrush` + 蓝边，比在卡片上加虚线框更容易看清落点。
- **任务卡**：左侧 3px 优先级色条（复用 `Border.priority-bar`），标题两行封顶，
  下面「项目点 + 项目名」，最后一行元信息（截止 / 预估 / 优先级）合成一个字符串。
  标题用 `FontBody`：它是一屏的主内容，不能按次级字号处理。
- **项目卡**：名称 + 色点、描述两行、38px 进度环 + 统计、`进入任务看板 →` 文字链接。
  统计只写「N 个任务」——列最窄到 170 出头，再加「进行中 N」会被裁成半句。
- **概览条**：`Button.stat`（数字 15px 半粗 + 标签 12.5px 灰字），选中态淡蓝底 + 蓝边；
  逾期、已阻塞在数字非零时才染语义色，其余保持正文色，否则每个数字都在喊。
- **已完成列**默认只留近 7 天，列头右侧放一个 `ghost sm` 按钮在「显示全部 / 只看近 7 天」间切换。

### 提醒页

三组纵向排列：**待处理 → 待触发 → 已处理**，空组整组隐藏（不留一个「0 条」的空壳）。

- 行复用 `Border.task-row`，列宽 `Auto,*,Auto`：左侧 3px 状态条（仅待处理可见）→ 标题 + 元信息 → 状态 chip + 动作。
- **「待处理」必须有暖底 + 琥珀竖条**（`Border.task-row.alert` + `WarningSoftBrush`）。
  只靠 chip 区分时，待处理和待触发在深色下几乎一模一样 —— 一个是「压着的事」，一个是「将来的事」，
  扫一眼就要能分开，所以用**底色**（整行）而不是再加一个色块。
- 行内最多四个图标：`Check`（标记已处理）/ `Clock`（10 分钟后再提醒）/ `Close`（忽略）/ `Trash`（`dangerish` 删除）。
  它们靠 `IsActionable` / `IsTriggered` 条件显隐：只留当下真能做的动作，不给一排灰按钮。
- 时间用相对口径（今天 / 明天 / 昨天 / 周X / MM-dd），跨年才补年份 —— 提醒是「马上要发生的事」，
  绝对时间戳反而要多读一遍。逾期转 `WarningBrush`。
- 顶部一行说明文字（`FontXs` + `dim`）解释「这些提醒从哪来」，右侧才是唯一主操作「新建提醒」。
  说明不能省：三类提醒混在一张列表里，没有这句话用户分不清哪条是任务带的、哪条是站会。

### 设置页

四张分组卡：**外观 / 提醒 / 数据 / 关于**。每张卡是「14px 半粗标题 + 一句灰色说明 + 若干行」，
卡片之间 16px，行之间靠 `LineBrush` 分隔线而不是再加边框。

- **每个开关都必须有一句「关掉会怎样」**：`关闭窗口时驻留托盘` 下面是「关掉就是退出：不再接收提醒，
  直到下次打开」；只写开关名，用户得先试一遍才知道后果。开关本身不解释自己。
- 站会时间用下拉（06:00–22:00 半点步进），不用裸时间输入框：这类时间只取整点和半点，
  让用户手打 `9:5` 再报错是自找麻烦。历史值不在预设里时补进选项，避免打开设置页就把用户的旧值冲掉。
- 「数据」卡里的路径用 `SelectableTextBlock.mono`：可选中、等宽，方便直接复制去备份。

### 托盘与通知

- **通知走应用内而不是系统 Toast**：Windows Toast 需要 AUMID 与打包身份，单文件未打包 exe 上会静默失败；
  `WindowNotificationManager` 三平台行为一致。落点固定在窗口右下角，最多同时 3 条、10 秒自动消失。
- 通知只承载「一件事 + 一个落点」：点任务提醒直接开那条任务的抽屉，点站会通知切到今日看板。
- 托盘菜单只放四项：打开工作台 / 今日看板（逾期 N）/ 未处理提醒（N）/ 退出。
  **托盘不是第二个应用**，塞满导航项只会让人在两层导航之间犹豫；数字只写进菜单标题，不额外做角标。
- 托盘建不出来（部分 Linux 桌面无 StatusNotifier 主机）时安静降级：关窗口即退出，
  否则窗口一关进程就再也找不回来。

### 命令面板与徽标

- 面板 `Border.palette`：580 宽、距顶 88、`RadiusLg` + 大阴影，遮罩用 `ScrimBrush`。
- 结果行是 `Button.palette-row`（透明底、`RadiusSm`、选中态 `AccentSoftBrush`），
  左侧 26px 方形字形块 + 标题 + 右侧灰色来源标签（跳转 / 动作 / 帮助 / 项目 / 任务）。
- 侧边栏徽标 `Border.badge`：`DangerSoftBrush` 底 + `DangerBrush` 字，只挂在「看板」上，
  数字是全局逾期数；没有逾期时整个徽标隐藏，不留一个「0」占位。
- 快捷键说明里的按键用 `TextBlock.key`（等宽字体 + `FontXs`），靠字体而不是色块区分。
- **设置不进导航**：它是低频入口，占一格导航会把「看板 / 任务 / 项目」这条主线稀释掉。
  现在收在侧边栏左下角：`icon` 按钮（`Settings` 图标，当前在设置页时加 `tinted`），
  右边跟版本号 `V 1.0.1`（`FontMicro` + `TextDimBrush`）。版本号取程序集版本，
  发版只改 `WorkStation.App.csproj` 的 `<Version>`。

## 6. 已知取舍

- **行内操作只给图标**：文字按钮（编辑 / 删除）在列表里占据一整段宽度，而且和正文同字号，
  看起来像可点的词而不是按钮。换成图标后单行宽度省下约 60px，代价是首次使用要靠 tooltip 认，
  所以图标按钮强制带 `ToolTip.Tip`。
- **对话框里的「取消 / 保存」保留文字**：图标化之后「取消」只能画成叉，与右上角关闭撞车，
  而且这两颗是全屏唯一的收尾动作，文字更稳。
- **状态用圆点 + 文字，不用色块胶囊**：白卡上的浅灰底几乎不可见，反而像文字溢出了底色。
- **圆角按层级而不是按高度**：早先越高的控件越圆，弹窗和看板列都接近胶囊；
  现在固定 4 / 6 / 8，靠「内层比外层小」表达嵌套，视觉上更硬朗也更像桌面软件。
- **进度环颜色跟随项目色，无项目色时回落强调色**：早先直接绑 `AccentBrush`，
  无色的项目会解析成 `Transparent`，整个环直接消失。
- **深色主题下强调色提亮**（`#6E97FF`）：沿用浅色值会在深底上糊成一团。
- **看板不做横向滚动**：把 `UniformGrid` 放进横向 `ScrollViewer` 时，测量阶段拿到的是无限宽度，
  单元格会按最长文本撑开，四列直接溢出并被裁掉。改成四列等分自适应后，1024 最小宽度下
  每列约 175px，卡片标题最多两行——这是「一屏看全」换取的空间代价，比切掉半列更可接受。
- **视图模型里取主题画刷必须带 `ActualThemeVariant`**：`TryGetResource(key, null, …)` 会落到
  默认（浅色）字典，深色界面上概览数字会取到近黑色，等于看不见。统一走 `ThemeBrushes.Get`。
- **通知只在应用内弹，不做系统 Toast**：Windows Toast 需要 AUMID 与打包身份，单文件未打包的 exe
  上会静默失败 —— 表现为「设了提醒却没反应」，比没有通知更糟。代价是窗口被完全收起时（用户手动最小化
  到托盘之外）看不到通知，只能靠托盘 tooltip 与徽标提醒。等真做了打包分发再补系统通知。
- **提醒页不做按项目 / 来源筛选**：三类提醒合起来通常十几条，加一条筛选栏会把这个页面变成第二个任务页；
  要定位具体某条，用 `Ctrl+K` 搜。分组（待处理 / 待触发 / 已处理）已经是这一屏最有效的切分。
- **托盘菜单只列四项，不列「今日前 5 项任务」**：设计稿里有过这一项，实测在原生菜单里读起来像
  一份缩水版的看板，而且每次刷新都要重建菜单项。今日口径点「今日看板」一格到位。

## 7. 复查方式

可视化验证靠无头宿主做真实光栅化（`TestAppBuilder` 里 `UseHeadlessDrawing = false` + `UseSkia`），
把 `MainWindow` 直接渲染成 PNG 逐张核对。需要复核时临时写一个截图用例即可，**不要提交**——
它依赖固定的种子数据，不适合当回归测试。
